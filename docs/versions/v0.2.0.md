# v0.2.0 — AI Provider Foundation

> WP AI Chat Lab 的第一个正式代码实验版本。

**版本：v0.2.0**  
**阶段：AI Provider Foundation**  
**状态：Implementation Complete / Awaiting Real WordPress Test**

---

## 1. 版本目标

v0.1.0 已经回答“为什么做”和“准备做成什么”。

v0.2.0 只回答一个更小的问题：

> **WordPress 如何以稳定、可测试、可替换的方式连接 AI Provider，并首先跑通 DeepSeek？**

本版本不开发 Knowledge、RAG、聊天窗口或人工接管。

---

## 2. 核心架构

```text
WordPress Admin
      ↓
AI Manager
      ↓
AI Provider Interface
      ↓
DeepSeek Provider
      ↓
DeepSeek API
      ↓
Unified Response
```

业务层以后只依赖 `AI Manager`，不直接依赖 DeepSeek URL 或具体模型实现。

---

## 3. Provider Contract

`WPAIC_AI_Provider_Interface` 当前定义：

```text
get_id()
get_name()
get_models()
is_configured()
test_connection()
chat()
```

Provider 负责：

```text
Authentication
Model
HTTP Transport
Timeout
Response Parsing
Usage Parsing
Error Normalization
Elapsed Time
```

Provider 不负责：

```text
Knowledge
Retrieval
Grounding
Business Prompt
Conversation
Lead
Human Handoff
Usage Limits
```

原则：

> **Provider = Transport + Normalization**

---

## 4. DeepSeek 基线

v0.2.0 使用：

```text
API:
https://api.deepseek.com/chat/completions

Model:
deepseek-flash

Streaming:
false

Thinking:
disabled
```

本版本只在设置界面暴露 `deepseek-flash`，避免第一轮实验产生无意义的模型分支。

Thinking 被显式关闭，因为当前只是 Provider Transport 测试，不需要默认推理模式带来的额外复杂度和 Token。

---

## 5. API Key 策略

支持两个来源：

### wp-config.php

```php
define( 'WPAIC_DEEPSEEK_API_KEY', 'YOUR_API_KEY' );
```

### WordPress Option

后台保存到：

```text
wp_options → wpaic_settings
```

优先级：

```text
wp-config.php Constant
        ↓
WordPress Option
        ↓
None
```

后台不会把已经保存的真实 API Key 重新输出到 HTML。

## 7. Unified Response

Provider 成功响应统一为：

```text
content
provider
request_model
response_model
usage
finish_reason
elapsed_ms
status_code
```

未来增加其他 Provider 时，上层业务模块不需要改变返回结构。

## 8. Error Model

当前明确区分：

```text
wpaic_ai_missing_key
wpaic_ai_empty_messages
wpaic_ai_invalid_messages
wpaic_ai_transport_error
wpaic_ai_timeout
wpaic_ai_auth_error
wpaic_ai_rate_limited
wpaic_ai_provider_error
wpaic_ai_invalid_response
wpaic_ai_empty_response
wpaic_ai_invalid_model
wpaic_ai_api_error
wpaic_ai_provider_not_found
```

重要原则：

> **Provider Failure ≠ AI 不知道。**

未来 Knowledge Gap 不能把网络错误、认证错误或 Provider 故障误判为“知识不足”。

---

## 9. 安全与边界

后台配置、连接测试和最小 AI 测试仅允许 `manage_options`。

AJAX 测试使用：

```text
Capability Check
+
Nonce
```

测试输入最长 1000 字符。

测试按钮请求期间自动禁用，减少慢网和重复点击造成的重复 API 请求。

AI 返回文本通过前端安全转义显示，不直接注入模型 HTML。

## 13. 测试清单

真实 WordPress 环境需要依次验证：

1. 安装 / 激活 / 停用无 Fatal Error。
2. 未配置 API Key 时提示明确。
3. 错误 API Key 返回认证错误。
4. 正确 API Key 可连接。
5. `WPAIC_DEEPSEEK_API_KEY` 常量优先。
6. 最小英文测试正常。
7. 中文测试正常。
8. Usage 可读取。
9. Request / Response Model 可显示。
10. Elapsed Time 可显示。
11. 空问题不能发送。
12. 超过 1000 字符测试问题被阻止。
13. 无效 Model 安全回退或明确报错。
14. 断网返回 Transport Error。
15. 超时返回 Timeout。
16. 慢网期间按钮禁用，请求完成后恢复。
17. 连续点击不会轻易产生重复请求。

## 14. Acceptance Criteria

v0.2.0 只有在以下条件成立时才能正式封版：

- 插件可正常安装、激活、停用。
- Admin UI 与 Provider Transport 分离。
- DeepSeek API URL 只存在于 DeepSeek Provider。
- AI Manager 可以统一调用当前 Provider。
- API Key 缺失、错误和正确三种情况均有稳定结果。
- 最小 Chat 请求成功。
- 成功响应统一包含 content / provider / model / usage / elapsed 等字段。
- 所有基础设施错误使用 `WP_Error`。
- `wp-config.php` Key 优先于数据库 Key。
- 后台操作具备 Capability + Nonce。
- 不创建自定义数据库表。
- 不混入 Knowledge / Retrieval / Chat / Lead / Human 等后续模块。

## 15. 当前实现结果

代码已经实现：

```text
WordPress Admin
      ↓
WPAIC_AI_Manager
      ↓
WPAIC_AI_Provider_Interface
      ↓
WPAIC_DeepSeek_Provider
      ↓
DeepSeek Chat Completions API
      ↓
Unified Response
```

当前实现已经完成：

- PHP 结构设计；
- Admin 设置页；
- API Key 双入口；
- Non-streaming Chat；
- Thinking Disabled；
- Error Normalization；
- AJAX 测试；
- 重复点击保护；
- 版本文档与 CHANGELOG。

### 真实环境测试结果

已在真实 WordPress + DeepSeek 环境完成本版本核心与边界测试，包括：

- 正确 / 错误 / 空 API Key；
- `WPAIC_DEEPSEEK_API_KEY` 常量优先；
- 连接测试与中文最小对话；
- Usage、Request / Response Model、Elapsed、Finish Reason 与 HTTP Status；
- 断网、慢网与重复点击保护。

测试未发现功能异常。Final Review 中发现保存设置后成功 Notice 重复显示，现已将成功通知从 `sanitize_settings()` 移至 `settings-updated=true` 的页面渲染阶段，避免 sanitize callback 被重复执行时产生重复 Notice。

v0.2.0 当前进入 Final Review，不再增加新功能。
