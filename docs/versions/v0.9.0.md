## 1. 版本定位

v0.9.0 不把 WP AI Chat Lab 扩展成完整 CRM，也不进入实时人工客服。

本版本只解决两个业务问题：

1. **什么时候应该自然地邀请访客提交询盘？**
2. **询盘提交后，WordPress 后台如何保存、查看和处理？**

整体路径：

```text
Knowledge
↓
Retrieval
↓
Grounding
↓
Usage Guard
↓
Chat
↓
Lead Trigger Policy
↓
Inquiry Form
↓
Inquiry Service / Repository
↓
wp_wpaic_inquiries
↓
后台 Inquiry Management
```

核心原则：

> **先帮助，再转化。**  
> AI 的首要任务仍然是可靠回答问题；只有在用户主动表达需求、AI 无法继续帮助或业务边界自然出现时，系统才提供询盘入口。

## 2. 架构边界

Chat 与 Inquiry 必须保持独立：

```text
Chat Response
     ↓
Lead Trigger Policy
     ↓
Should Offer Lead?
 ┌──────┴──────┐
 No            Yes
 ↓              ↓
继续聊天        CTA
                 ↓
             用户主动点击
                 ↓
           Inline Inquiry Form
                 ↓
           Inquiry Controller
                 ↓
            Inquiry Service
                 ↓
          Inquiry Repository
                 ↓
         wp_wpaic_inquiries
```

Lead Trigger Policy **只决定是否显示邀请**，不能直接保存询盘，也不能强制弹出表单。

## 3. Lead Trigger Policy

第一版采用 **Deterministic Policy（确定性规则）**，不额外调用 AI 判断购买意图。

### 3.1 Trigger Types

第一版只保留四类：

```text
manual
commercial_intent
no_answer
usage_blocked
```

### 3.2 manual

用户主动点击：

- Request a Quote
- Contact Sales
- Leave a Message

这是最高确定性的询盘入口。

### 3.3 commercial_intent

当问题包含明确商业需求关键词时，Chat 仍优先正常回答，然后在回答下方显示 CTA。

示例：

```text
Can I get a quote for 500 sqm CWC-610?
↓
正常 answer
+
Request a Quote CTA
```

### 3.4 no_answer

当现有知识不足以可靠回答时：

```text
no_answer
↓
提示当前知识不足
↓
Leave a Message CTA
```

这是“AI 解决不了 → 留给团队后续处理”，不是实时 Human Handoff。

### 3.5 usage_blocked

- `conversation_limit_reached`：主要 CTA 仍是 Start New Conversation，询盘 CTA 只作为次级入口。
- `visitor_daily_limit_reached`：可以明显提供 Leave Your Requirement。
- `site_daily_limit_reached`：AI 暂时不可继续时，询盘是自然 fallback。

### 3.6 不自动触发 Lead 的情况

以下状态默认不显示自动 Lead CTA：

```text
clarify
Weak
Medium
ordinary answer without commercial intent
HTTP 429 request rate limit
HTTP 503 provider error
network error
invalid conversation
```

系统故障、滥用保护或问题不够明确时，不应该借机强制收集个人信息。

## 4. Commercial Intent Keywords — 后台完全可配置

这是 v0.9.0 的固定产品原则：

> **商业需求关键词不能写死在代码中。**

插件只提供一组默认值，管理员可以在后台完整控制。

### 4.1 后台能力

第一版设置页至少支持：

- 查看默认关键词；
- 添加关键词；
- 删除关键词；
- 修改关键词；
- 一行一个关键词 / 短语；
- 保存后立即生效；
- 恢复默认关键词；
- 允许保存空列表。

**空列表的语义：关闭 commercial_intent 关键词触发。**

插件不能在管理员清空后自动重新写入默认值；只有管理员主动点击“恢复默认关键词”时才恢复。

### 4.2 默认关键词（初始建议）

```text
quote
quotation
price
pricing
sample
order
MOQ
minimum order
bulk
custom
customized
OEM
ODM
distributor
dealer
shipping
delivery
contact sales
```

默认值只是开箱即用起点，不代表固定规则。

### 4.3 多语言

设置应允许任意 Unicode 文本，因此管理员可以自行增加：

```text
报价
价格
样品
起订量
定制
代理
经销商
交期
联系我们
```

或其它语言关键词。

### 4.4 存储建议

使用 WordPress Option 保存标准化后的关键词数组，例如：

```text
wpaic_lead_commercial_keywords
```

不为关键词单独创建数据库表。

### 4.5 匹配原则

第一版保持简单、可解释：

- Trim + 去除空项；
- 去重；
- Latin 文本大小写不敏感；
- 支持多词短语；
- 不调用 AI；
- 每一次匹配结果都应能从后台配置中解释。

后续若真实数据表明误判明显，再升级规则，不提前引入复杂 NLP / Lead Scoring。

## 5. Trigger Priority

当同一请求同时满足多个触发条件时，第一版建议固定优先级：

```text
manual
↓
commercial_intent
↓
no_answer
↓
usage_blocked
```

示例：问题本身明确要求报价，即使最终知识不足，也优先使用 `commercial_intent` 的 Request a Quote CTA，而不是泛化的 Leave a Message。

## 11. Spam / Abuse Foundation

第一版只做最小防护：

### Honeypot

隐藏字段，例如：

```text
website
```

正常用户为空；非空直接拒绝。

### Submission Rate Limit

使用短期 Transient，例如：

```text
同一 Visitor：5 submissions / hour
```

不混入 AI Usage Counter。

### Server Validation

至少包括：

```text
Name length
Email format
Message length
Phone length
Company length
Trigger allowlist
Conversation UUID
```

### 暂不加入 Turnstile

真实上线出现明显垃圾询盘后，再评估 Cloudflare Turnstile。

---

## 12. Database Failure Policy

Inquiry 写入与普通 Chat 不同：不能出现“UI 显示提交成功，但数据库实际失败”。

必须：

```text
Repository Insert
↓
明确确认成功
↓
才返回 Public Success
```

数据库写入失败：

```text
HTTP 500
public error
```

严格 fail closed。

## Stage 1 Round 2 — Inquiry Capture Foundation — Validation Passed / Sealed

Round 2 已建立真实 Inquiry Capture Boundary，并完成真实 WordPress 验收；正式 Chat Widget 在本轮仍未修改。

```text
POST /wp-json/wpaic/v1/inquiry
↓
Inquiry Context
↓
Honeypot
↓
Visitor Submission Rate (5 / hour)
↓
Server Validation
↓
Inquiry Service
↓
Inquiry Repository
↓
wp_wpaic_inquiries
```

### 数据库

DB Version 从 `1.1` 升至 `1.2`，新增：

```text
wp_wpaic_inquiries
```

核心字段：`status / name / email / phone / company / message / trigger_type / conversation_id / source_url / last_question / visitor_hash / created_at / updated_at`。

不保存原始 Visitor UUID、不保存 IP、不保存完整 Conversation Transcript、Prompt 或 AI Answer。

### Public Contract

成功：HTTP `201`：

```json
{
  "type": "submitted",
  "message": "Thank you. Your request has been submitted successfully."
}
```

公开响应不返回数据库 ID、Visitor Hash 或其它内部诊断字段。

### Anti-abuse

- Honeypot 在 Rate consumption 之前拒绝。
- 同一 Visitor 默认最多 `5 submissions / hour`。
- Inquiry Rate 与 Chat Public Request Guard / Provider Usage Guard 相互独立。
- 管理员 Lab 只允许重置当前浏览器 Visitor 的 Inquiry Rate，不删除已保存 Inquiry。

### Round 2 Validation Checklist

1. 正常提交 → HTTP 201 / `submitted` / Rows +1。
2. Name / Email / Message 必填校验 → HTTP 400 / 不写库。
3. 非法 Email → HTTP 400 / 不写库。
4. 非法 Conversation UUID → HTTP 400 / 不写库。
5. Trigger 非 allowlist → HTTP 400 / 不写库。
6. Honeypot → HTTP 400 / 不写库 / 不消耗 Inquiry Rate。
7. 同 Visitor 第 6 次提交 → HTTP 429 / `Retry-After` / 不写库。
8. 数据库存储 Visitor Hash，不存 raw Visitor UUID / IP。
9. Repository 写入只有成功后才允许返回 HTTP 201；强制 DB Failure Injection 留到 Stage 3 Operational Validation。

### Round 2 Real Validation Result

真实 WordPress 验收结果：

1. 正常 Public Inquiry → HTTP `201` / `submitted` / Rows +1 / `status = new`：✅
2. Name 必填校验 → HTTP `400` / Rows 不增加：✅
3. 非法 Email → HTTP `400` / Rows 不增加：✅
4. 非法 Conversation UUID → HTTP `400` / Rows 不增加：✅
5. Trigger 非 allowlist → HTTP `400` / Rows 不增加：✅
6. Honeypot → HTTP `400` / Rows 不增加 / Inquiry Rate 不增加：✅
7. 同一 Visitor 重置 Rate 后连续提交：前 5 次成功，第 6 次 HTTP `429` + `Retry-After`，Rows 不增加：✅
8. 数据库只保存 Visitor Hash，不保存 raw Visitor UUID / IP / 完整 Conversation：✅
9. Repository 只有 Insert 成功后才返回 HTTP `201`；强制 DB Failure Injection 保留到 Stage 3：实现边界已就绪，故障注入待后续专项验证。
