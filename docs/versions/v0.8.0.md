# v0.8.0 — Chat Integration

> 当前状态：Stage 1 — Public Chat Boundary Foundation / Validation Passed / Sealed

## 一、版本目标

v0.8.0 不重新开发 AI Engine，而是把 v0.5.0～v0.7.0 已验证的能力接到真实匿名访客入口：

```text
Visitor
  ↓
Public Chat Boundary
  ↓
Conversation / Visitor / Site Context
  ↓
WPAIC_Grounded_Answer_Service
  ↓
Local Retrieval → Grounding Gate → Usage Guard → AI Provider
```

核心原则：**Chat 只是入口，不拥有 AI 逻辑。**

## 二、参考源码定位

- `simple-live-chat`：Stage 2 前端 UI 基线。
- `wp-live-chat-inquiry`：Visitor / Conversation / REST / State 架构参考，不整体合并。
- `wp-ai-chat-lab`：唯一正式插件主体与 AI 核心。

## 三、Stage 1 已实现

- `POST /wp-json/wpaic/v1/chat`
- Conversation UUID：请求未提供时服务器生成并返回
- Visitor UUID：服务器生成，使用 `wpaic_visitor` HttpOnly Cookie 持久化
- Site Context：服务器生成，Public Request 无法覆盖
- Public Contract：`answer / clarify / no_answer / blocked / error`
- Public Response 不暴露 Retrieval Score、Provider、Model、Token、Usage Hash、内部 Reason Code
- Admin `Chat Boundary` Playground 直接调用真实 Public REST
- Usage Counter 必须为 InnoDB；不满足 transaction / row-lock prerequisite 时 fail closed
- Transaction-critical wpdb failure 明确 rollback + `usage_guard_unavailable`

## 四、数据库

- Plugin Version：`0.8.0`
- DB Version：`1.1`
- 新增表：0
- 仍只有 Knowledge Store + Usage Counter

## 五、Public Request

```json
{
  "question": "What are the dimensions of CWC-610?",
  "conversation_id": "optional UUID v4"
}
```

Public Client 不能控制 Visitor / Site、Provider / Model、Usage Limit、Grounding Threshold、Candidate Limit 或 Top K。

## 六、Stage 1 真实验收结果

真实 WordPress 环境已按 1 → 7 连续完成验收，全部符合预期：


1. 首次匿名 Strong：HTTP 200 / `answer`；服务器创建 Conversation + Visitor；真实 AI Answer 返回。✅
2. 同一 Conversation 第二次 Strong：Conversation / Visitor 均为 existing，Conversation ID 保持不变。✅
3. Weak：HTTP 200 / `clarify`；不进入 Provider。✅
4. Medium：HTTP 200 / `clarify`；不进入 Provider。✅
5. None：HTTP 200 / `no_answer`；不进入 Provider。✅
6. Strong #3：Conversation 已达 2/2，HTTP 200 / `blocked`；Provider 不调用。✅
7. 非法 Conversation ID：HTTP 400 / `error`；在进入 Grounded Answer Service 前拒绝。✅
8. 场景 6 反向确认 Weak / Medium / None 没有消耗 AI Usage。✅
9. Public Response 不出现 Provider、Model、Token、Score、Hash、内部 Reason Code。✅
10. Usage Counter = InnoDB / Transactional = Yes；Public Reservation 前置条件通过。✅

**Stage 1 结论：Validation Passed / Sealed。**

## 七、Stage 1 明确不做

- 正式 Chat Widget
- Conversation / Message 表
- Chat History / Admin Inbox
- Lead / Human Handoff / Agent
- Streaming / Cost Guard / Embedding / Vector / RAG
- Public Endpoint Request Rate Limit（后续 Public Hardening）

## 八、Lab 页面长期保留原则

Chat Boundary Playground 将永久保留。后续正式 Chat UI 上线后，它仍用于直接测试 Public REST、Conversation / Visitor Context、Public Contract 与输入校验。

同时，Knowledge / Retrieval / Grounded AI / Usage Guard 等既有 Lab 页面也继续作为长期教学、诊断和回归工具保留；可以优化展示，但不删除核心测试能力。详见 `docs/lab-validation-policy.md`。
